# Как подготовить реферат в Typst и отправить его в GitHub

Эта инструкция рассчитана на тех, кто впервые работает с Typst и GitHub.

## Что должно получиться

Для одного реферата в вашей рабочей ветке должны быть два файла:

- `referat.typ` — исходный документ, который можно редактировать;
- `referat.pdf` — готовый PDF, который можно прочитать без Typst.

Общий файл `template.typ` — это заготовка. Его не заполняют напрямую и не заменяют своей работой: сначала делают копию.

## Часть 1. Создайте свою ветку

1. Откройте репозиторий `JetBape/ISIT_GF26-02B`: https://github.com/JetBape/ISIT_GF26-02B
2. Перейдите на вкладку **Code**.
3. Откройте список веток (обычно там написано `main`).
4. Введите название новой ветки, например `feat/ваш-ник-topic-1`, и создайте её на основе `main`.

Пример для участника с ником `gnida12886`, работающего над темой 1: `feat/gnida12886-topic-1`.

Работайте в своей ветке, а не напрямую в `main`.

## Часть 2. Скопируйте шаблон

1. Убедитесь, что открыта ваша новая ветка.
2. Найдите `template.typ` в корне репозитория.
3. Откройте файл и скопируйте его содержимое.
4. Создайте папку для своей работы, например `reports/topic-1/`.
5. В этой папке создайте файл `referat.typ` и вставьте туда скопированный текст.

Итоговая структура может выглядеть так:

```text
ISIT_GF26-02B/
├── template.typ
├── README.md
└── reports/
    └── topic-1/
        ├── referat.typ
        └── referat.pdf
```

Папка и имя файла — пример. Если для темы уже согласовано другое расположение, используйте его.

**Не редактируйте `template.typ` вместо копии.** Иначе можно случайно изменить общий шаблон для всех.

## Часть 3. Заполните `referat.typ`

Откройте `referat.typ` в редакторе текста или кода, который поддерживает обычные текстовые файлы. Можно использовать редактор Typst или другой подходящий редактор.

В начале файла находятся поля с данными. Замените значения в кавычках на свои:

- `university` — название университета;
- `institute` — институт;
- `department` — кафедра, если она требуется;
- `discipline` — дисциплина;
- `topic` — тема реферата;
- `group` — номер группы;
- `authors` — имена участников;
- `teacher` — имя преподавателя;
- `city` и `year` — город и год.

Например, строка:

```typst
#let topic = "[Название темы реферата]"
```

может стать такой:

```typst
#let topic = "Технологии создания и обработки текстовых документов"
```

Меняйте текст в кавычках, но не удаляйте `#let`, имя переменной, кавычки и знак `=`.

Далее по документу замените подсказки в квадратных скобках своим текстом. Например:

```typst
[Объясните актуальность темы, сформулируйте цель и задачи работы.]
```

нужно заменить настоящим введением. Саму подсказку в итоговой работе оставлять нельзя.

В основной части названия разделов должны соответствовать вопросам вашего семинара. Добавляйте разделы или подразделы, если вопросов больше. Не оставляйте примерные названия разделов, квадратные скобки и учебные подсказки в готовом реферате.

В списке источников замените примеры реальными источниками, которые вы использовали. Не оставляйте `https://example.com` и выдуманные библиографические данные.

## Часть 4. Получите PDF

Typst превращает исходный файл `.typ` в PDF.

### Вариант A. Через Typst Web App

1. Откройте веб-редактор Typst: https://typst.app/
2. Создайте документ или проект.
3. Перенесите содержимое `referat.typ` в редактор.
4. Если редактор показывает ошибки, исправьте их.
5. Экспортируйте документ в PDF.

Интерфейс сайта может меняться; при необходимости ориентируйтесь на текущие подсказки самого редактора.

### Вариант B. Через установленный Typst CLI

1. Установите Typst CLI по официальной инструкции: https://typst.app/open-source/
2. Откройте терминал в папке, где лежит `referat.typ`.
3. Выполните команду:

```bash
typst compile referat.typ referat.pdf
```

Если исходный файл находится в другой папке, укажите путь к нему и к PDF. Например:

```bash
typst compile reports/topic-1/referat.typ reports/topic-1/referat.pdf
```

Если появилась ошибка, не переименовывайте файл наугад: сохраните текст ошибки и попросите помощи у команды.

**Важно:** шрифт PT Serif должен быть доступен в системе или среде компиляции. Файлы шрифта в репозиторий не добавляйте.

## Часть 5. Проверьте готовую работу

Перед отправкой убедитесь, что:

- [ ] в титульном листе правильные тема, авторы, группа и преподаватель;
- [ ] заменены все подсказки в квадратных скобках;
- [ ] содержание соответствует реальным заголовкам;
- [ ] основная часть раскрывает вопросы семинара;
- [ ] есть введение, заключение и список использованных источников;
- [ ] источники настоящие и оформлены последовательно;
- [ ] PDF открывается и страницы выглядят нормально;
- [ ] в папке лежат оба файла: `referat.typ` и `referat.pdf`.

По требованиям преподавателя готовые исходник и PDF должны быть в репозитории не позднее чем за 12 часов до семинара.

## Часть 6. Добавьте файлы в свою ветку

На сайте GitHub:

1. Убедитесь, что выбрана ваша ветка, а не `main`.
2. Откройте нужную папку.
3. Нажмите **Add file → Upload files** или **Add file → Create new file**.
4. Добавьте `referat.typ` и `referat.pdf`.
5. В сообщении коммита напишите, что изменили, например: `Add report for topic 1`.
6. Сохраните изменения в своей ветке.

Если вы работаете через Git локально, добавьте файлы, сделайте коммит и отправьте ветку на GitHub обычным для вашей команды способом.

## Часть 7. Создайте Pull Request

1. Откройте репозиторий и выберите свою ветку.
2. Нажмите **Compare & pull request**. Если кнопки нет, откройте вкладку **Pull requests → New pull request**.
3. Укажите базовую ветку `main`, а ветку-источник — свою ветку.
4. В заголовке укажите тему, например `Report: topic 1 — text documents`.
5. В описании коротко перечислите, что добавлено, и подтвердите, что PDF проверен.
6. Создайте Pull Request.
7. Дождитесь проверки и одобрения другого участника. Исправьте замечания, если они появятся.

Не сливайте изменения в `main` самостоятельно в обход принятого порядка проверки.

## Частые ошибки

- **Редактируют `template.typ` напрямую.** Создайте копию `referat.typ`.
- **Загружают только PDF.** Нужны и исходник `.typ`, и PDF.
- **Забывают заменить подсказки.** Найдите в документе все квадратные скобки перед сдачей.
- **Оставляют примерные источники.** В списке должны быть источники, которые действительно использовались.
- **Пытаются открыть `.typ` как готовый PDF.** `.typ` — исходник; для чтения итоговой работы используйте PDF.
- **Работают прямо в `main`.** Создайте отдельную ветку и откройте Pull Request.

Если что-то не получается, напишите, на каком шаге остановились, и приложите скриншот или текст ошибки.
